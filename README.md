# Bifrost

**An LLM router that picks the cheapest model that still answers well.**

Bifrost is a drop-in gateway that speaks the OpenAI API. Point an existing client at it by changing one line, and each request is routed to the model that is predicted to answer well at the lowest cost. Every decision is logged against an "always use the premium model" baseline, so you can see what you saved and why.

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8080/v1", api_key="dev-local-key")

resp = client.chat.completions.create(
    model="auto",  # the model field is ignored; Bifrost picks the model
    messages=[{"role": "user", "content": "Reformat this JSON as YAML: {...}"}],
)
```

Most traffic (reformatting, extraction, simple Q&A, boilerplate code) gets answered just as well by a model that costs 20–50× less. Nobody downgrades by hand because the tradeoff is invisible and per prompt. Bifrost makes that call automatically and shows its work.

> **Status:** hackathon-stage project. The routing path, playground and dashboard work end to end locally. Streaming, response caching, and deployment are not done yet. See [Status](#status).

## How it works

```
┌──────────────┐
│ OpenAI SDK   │  base_url swap, no other change
│ or playground│
└──────┬───────┘
       │ POST /v1/chat/completions
       ▼
┌────────────────────────────────────────┐
│ Gateway  (Rust · axum)        :8080    │
│  auth → /route → dispatch → respond    │
└───┬──────────────────┬─────────────────┘
    │ POST /route      │ chat request
    ▼                  ▼
┌──────────────┐   ┌────────────┐
│ Router ML    │   │ OpenRouter │  upstream LLM API
│ (FastAPI)    │   └────────────┘
│ :8000        │
│  embed (BGE) │
│  → k-NN      │
│  → score     │
└──────────────┘

Playground (Next.js :3000) ──► /route (ML) and gateway
Dashboard  (Next.js :3000) ──► Postgres (reads `requests`)
```

For each prompt:

1. **Embed.** The prompt is turned into a 384-dimensional vector with the local `BAAI/bge-small-en-v1.5` model, running on CPU through fastembed.
2. **Predict.** The k nearest prompts (default k = 10) in the RouterBench corpus are retrieved by cosine similarity. For each candidate model, the average of its observed quality on those neighbors is its predicted quality.
3. **Score.** Each candidate gets a composite score, `pred_quality − λ · cost_norm`, after hard filters on context length and max cost (see [Routing policy](#routing-policy)).
4. **Pick and explain.** The highest scoring candidate wins. The response includes every candidate's score, the neighbor prompts behind the decision, and a one-sentence summary with the estimated savings against the baseline model.

The ML service is a separate process so the gateway and routing can be developed and deployed independently. Both sides talk over a JSON contract, and the localhost hop costs about 1 ms against LLM calls that take seconds.

## Results

Evaluated on 200 held-out test prompts from RouterBench, never seen during training or indexing. Costs are estimated from registry prices. Source: [`router-ml/models/evaluation_results.csv`](router-ml/models/evaluation_results.csv), generated by `training/evaluate.py`.

| Mode | Avg quality | Avg cost (USD) | Cost savings | Quality retention |
|---|---:|---:|---:|---:|
| Always premium (GPT-5.5) | 0.795 | $0.003518 | 0.00% | 100.00% |
| `quality` (λ = 0.1) | 0.663 | $0.000795 | 77.41% | 83.33% |
| `balanced` (λ = 0.5) | 0.561 | $0.000172 | 95.10% | 70.60% |
| `cheap` (λ = 0.9) | 0.511 | $0.000106 | 96.99% | 64.31% |
| Random routing | 0.644 | $0.001122 | 68.11% | 80.97% |
| Always cheap (Qwen3.7 Flash) | 0.296 | $0.000046 | 98.69% | 37.26% |

**Read these numbers carefully.** The success criteria in [PRD.md](PRD.md) target at least 40% cost reduction and at least 95% quality retention. The `quality` mode meets the cost target but falls short on quality retention (83%). No single λ meets both targets on this run. Treat the table as the current baseline to improve, not as a finished result.

Also note:

- Quality labels come from RouterBench's own 0-shot evaluations. They are not a fresh judgment of each response.
- `prepare_data.py` falls back to a **synthetic** dataset if it cannot download RouterBench. Numbers produced from synthetic data are meaningless. Check which data you used before quoting any number.
- The corpus is capped at 1,000 training prompts by default (`MAX_CORPUS_SIZE`) to keep embedding fast.

## Quick start

### Prerequisites

| Tool | Version | Used for |
|---|---|---|
| Docker + Docker Compose | recent | Postgres |
| Rust (cargo) | 1.85+ (edition 2024) | Gateway |
| Python | 3.10+ | Router ML |
| Node.js | 20+ with npm | Web app |
| OpenRouter API key | — | Real upstream LLM calls ([openrouter.ai/keys](https://openrouter.ai/keys)) |

The router and playground can run without an OpenRouter key (see [Configuration](#configuration)). Real chat completions need one.

### 1. Clone and configure

```bash
git clone <repo-url> bifrost
cd bifrost
cp .env.example .env
cp web/.env.example web/.env.local
```

Edit `.env` and set `OPENROUTER_API_KEY`. The defaults for everything else work for local development.

### 2. Start Postgres

```bash
docker compose up -d
```

This starts Postgres 16 on `localhost:5432` (user, password and database are all `bifrost`). On first boot it applies every `.sql` file in `migrations/`, which creates the tables and seeds the six candidate models.

Check that it is healthy:

```bash
docker compose ps
```

### 3. Build the router's index (one-time)

The ML service needs a prebuilt vector index. Generated files are gitignored, so every machine builds its own.

```bash
cd router-ml
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

python training/prepare_data.py   # download RouterBench, write data/processed/{train,val,test}.csv
python training/train.py          # embed the training prompts → models/train_embeddings.npy
```

`train.py` checkpoints its progress and can be restarted safely if interrupted. The first run also downloads the BGE embedding model, which is cached after that.

Optional, to reproduce the results table:

```bash
python training/evaluate.py       # writes models/evaluation_results.csv
```

### 4. Run the router (port 8000)

From `router-ml/`:

```bash
uvicorn app.main:app --reload --port 8000
```

Check it:

```bash
curl http://localhost:8000/health
```

`"status": "ok"` means the corpus and embedding model loaded. `"error"` means startup failed. The startup error is printed to the console.

### 5. Run the gateway (port 8080)

From `gateway/`:

```bash
cargo run
```

The gateway reads the root `.env` automatically when run from `gateway/`. Check it:

```bash
curl http://localhost:8080/health
```

### 6. Run the web app (port 3000)

From `web/`:

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

- `/` is the landing page.
- `/playground` is the chat UI with the λ slider and explanation panel.
- `/dashboard` shows savings, model mix, the cost/quality scatter, and the request log.

The dashboard shows generated sample data until the `requests` table has real rows. To fill it with sample rows:

```bash
npm run seed
```

### 7. Try it

```bash
curl http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer dev-local-key" \
  -H "Content-Type: application/json" \
  -H "X-Bifrost-Lambda: 0.9" \
  -d '{"model":"auto","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

Or preview a routing decision with no upstream call and no spend:

```bash
curl http://localhost:8080/v1/route/preview \
  -H "Authorization: Bearer dev-local-key" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"explain vector clocks","candidates":["openai/gpt-5.5","openai/gpt-5-mini","qwen/qwen3.7-flash"],"policy":{"mode":"balanced","lambda":0.5,"max_cost_usd":0.01}}'
```

## Configuration

Each part of the system reads its own environment. Nothing is shared implicitly except through the values you copy across.

### Root `.env` (gateway, and the reference for the rest)

| Variable | Default | Used by | Description |
|---|---|---|---|
| `OPENROUTER_API_KEY` | — | gateway | Upstream key. Without it, chat requests return `502` with a clear message. |
| `BIFROST_API_KEY` | `dev-local-key` | gateway, web | Static bearer token that clients send to the gateway. Any string. |
| `DATABASE_URL` | `postgresql://bifrost:bifrost@localhost:5432/bifrost` | web | Postgres connection for the dashboard and seed script. |
| `GATEWAY_PORT` | `8080` | gateway | Port the gateway listens on. |
| `ML_PORT` | `8000` | reference | Documents the router port. The uvicorn command hardcodes `--port 8000`. |
| `WEB_PORT` | `3000` | reference | Documents the web port. The `dev` script hardcodes `--port 3000`. |
| `DEFAULT_MODEL` | `openai/gpt-5-mini` | gateway | Model used when the router is unreachable (fail-open). |
| `BASELINE_MODEL` | `openai/gpt-5.5` | reference | The fixed premium model every savings number is measured against. Changing it invalidates historical savings numbers. |
| `DEFAULT_LAMBDA` | `0.5` | reference | Default cost/quality tradeoff. `0` = pure quality, `1` = pure cost. |
| `EMBEDDING_MODEL` | `BAAI/bge-small-en-v1.5` | reference | Must match the model used to build the index. |
| `KNN_K` | `10` | router-ml | Number of neighbors per prediction. |

> **Known mismatch:** the gateway reads `ML_ROUTER_URL` (default `http://localhost:8000`), but `.env.example` documents `ML_SERVICE_URL`. Set `ML_ROUTER_URL` for the gateway until these are unified.

Router-only variables (read directly from the environment when the process starts):

| Variable | Default | Description |
|---|---|---|
| `KNN_K` | `10` | As above. |
| `MINIMUM_QUALITY_THRESHOLD` | `0` (off) | If set above 0, candidates predicted below this quality are excluded from the winner when any candidate clears it. |
| `MAX_CORPUS_SIZE` | `1000` | Training prompts embedded by `train.py`. Raise it for a better index; embedding time grows linearly. |

The router does not read `.env` itself. Export variables in your shell, or pass them on the command line, e.g. `KNN_K=20 uvicorn app.main:app --port 8000`.

### `web/.env.local`

| Variable | Default | Description |
|---|---|---|
| `GATEWAY_URL` | `http://localhost:8080` | Gateway the server routes call. The browser never sees this. |
| `ML_ROUTER_URL` | `http://127.0.0.1:8000` | Router the preview route calls when mock mode is off. |
| `BIFROST_API_KEY` | `dev-local-key` | Sent to the gateway as the bearer token. Keep it server-side. |
| `DATABASE_URL` | — | Required for the dashboard. The app throws a clear error if it is unset. |
| `BIFROST_MOCK` | `1` | `1` = fake chat replies and fake routing preview, no gateway needed. `0` = call the gateway and router for real. |
| `NEXT_PUBLIC_BIFROST_DEMO` | `1` | `1` = dashboard falls back to generated sample traffic when the database is empty or unreachable. `0` = show empty and error states. Real rows always win. |

Set `BIFROST_MOCK=0` once the gateway and router are running, to see real decisions in the playground.

## API reference

### Gateway (`:8080`)

All routes except `/health` require `Authorization: Bearer <BIFROST_API_KEY>`.

#### `GET /health`

Returns `{"status":"ok"}`.

#### `POST /v1/chat/completions`

OpenAI-compatible chat endpoint. Bifrost picks the upstream model and returns the upstream response unchanged.

Request headers (optional):

| Header | Values | Default | Effect |
|---|---|---|---|
| `X-Bifrost-Lambda` | number in `[0, 1]` | `0.5` | The cost/quality tradeoff for this request. Higher = cheaper. |
| `X-Bifrost-Mode` | `quality`, `balanced`, `cheap` | `balanced` | Forwarded to the router as a label only. It does **not** change λ. Use `X-Bifrost-Lambda` to control the tradeoff. |

Body: standard OpenAI chat completion body. The `model` field is accepted but overwritten by the routing decision.

Behavior to know about:

- The prompt is the content of the **last** message in `messages`. Earlier turns are not sent to the router.
- Candidates are hardcoded in `gateway/src/chat.rs` as the six models from the registry. Changing the candidate set means editing that list.
- `stream: true` returns `400`. Set `stream: false`. Streaming is not implemented yet.
- If the router is down or returns an error, the request goes to `DEFAULT_MODEL` and a warning is logged.
- The response is not written to the `requests` table yet. See [Status](#status).

Errors use the OpenAI error shape: `{"error":{"message":"...","type":"..."}}`.

#### `POST /v1/route/preview`

Returns the routing decision without calling any model. Passes the body straight through to the router's `/route`, so it accepts the same body as [`POST /route`](#post-route) below.

#### `POST /chat/completions`

Unversioned alias of `/v1/chat/completions`, kept for convenience.

### Router ML (`:8000`)

#### `GET /health`

```json
{
  "status": "ok",
  "embedding_model": "BAAI/bge-small-en-v1.5",
  "predictor": "knn",
  "corpus_loaded": true,
  "registry_count": 6
}
```

`status` is `"error"` until the registry, embedder and corpus have all loaded.

#### `POST /route`

Request:

```json
{
  "prompt": "explain vector clocks to a distributed systems junior dev",
  "candidates": ["openai/gpt-5.5", "openai/gpt-5-mini", "qwen/qwen3.7-flash"],
  "policy": { "mode": "balanced", "lambda": 0.5, "max_cost_usd": 0.01 }
}
```

- `candidates` must be non-empty (`400` otherwise). Unknown or disabled models are ignored.
- `policy.lambda` is the field name on the wire; the Python model is `lambda_`.
- `policy.max_cost_usd` is a hard filter on the estimated cost of the call.
- Returns `503` while the service is still loading.

Response:

```json
{
  "chosen": "openai/gpt-5-mini",
  "scores": [
    { "model": "openai/gpt-5-mini", "pred_quality": 0.72, "est_cost_usd": 0.000045, "est_latency_ms": 1300, "score": 0.72 },
    { "model": "qwen/qwen3.7-flash", "pred_quality": 0.45, "est_cost_usd": 0.000018, "est_latency_ms": 900, "score": 0.45 },
    { "model": "openai/gpt-5.5", "pred_quality": 0.95, "est_cost_usd": 0.001350, "est_latency_ms": 2400, "score": -0.05 }
  ],
  "explanation": {
    "method": "knn",
    "summary": "Routed to GPT-5 mini because across 10 similar prompts, it delivered comparable quality to GPT-5.5 at a fraction of the cost.",
    "neighbors": [
      { "prompt": "explain vector databases simply", "winner": "openai/gpt-5-mini", "sim": 0.92 }
    ],
    "baseline_model": "openai/gpt-5.5",
    "est_savings_usd": 0.001305
  },
  "timing_ms": { "embed": 4.12, "predict": 1.85 }
}
```

The `scores` array is sorted by score, highest first. `est_latency_ms` comes from the registry, not a measurement.

## Routing policy

For each candidate `m`:

```
q̂(m)       = mean quality of m over the k nearest training prompts
cost(m)    = (in_tokens · price_in + 250 · price_out) / 1e6
cost_norm  = min–max scaling of cost across the filtered candidates
score(m)   = q̂(m) − λ · cost_norm(m)
chosen     = argmax score(m)
```

Hard filters run before scoring:

1. **Context length.** A model whose context window is smaller than the prompt is dropped.
2. **`max_cost_usd`.** A model whose estimated cost exceeds the cap is dropped.
3. If every candidate is filtered out, the cheapest candidate is used.

The playground maps its modes to λ as a convenience. `quality` = 0.1, `balanced` = 0.5, `cheap` = 0.9. The router's `mode` field is only a label today; the decision is driven entirely by `lambda`.

For how the router handles a model with no data near the prompt, see [router-ml/README.md](router-ml/README.md).

Where model data lives:

- `router-ml/app/models_registry.json` holds the prices and metadata the router uses. It is read at startup, not from Postgres, so edit it and restart the router.
- `model_registry` in Postgres holds the same models for the web app and the dashboard.
- `gateway/src/chat.rs` holds the candidate list the gateway sends to the router.

These three are not yet a single source of truth. Keep them in sync by hand when you add or reprice a model.

## Database

Postgres 16, schema in [`migrations/001_init.sql`](migrations/001_init.sql).

| Table | Purpose |
|---|---|
| `model_registry` | Candidate models, USD prices per 1M tokens, context length, latency, enabled flag. |
| `requests` | One row per routed request. Powers the dashboard: cost, savings, chosen model, explanation. |
| `response_cache` | Exact-match response cache, keyed by prompt hash. Created, not yet used by the gateway. |

To reset the database from scratch:

```bash
docker compose down -v
docker compose up -d
```

Migrations only run on first boot of an empty volume. Later schema changes need a new migration file applied by hand.

**Working**

- Gateway: OpenAI-compatible `/v1/chat/completions` (non-streaming), bearer auth, OpenRouter dispatch, fail-open to a default model, `/v1/route/preview`.
- Router: embeddings, k-NN prediction, composite scoring with hard filters, explanations with neighbor prompts, timing info, health check.

- `GET /v1/route/explain?request_id=`.

- Gateway tests.
- Mobile check of the dashboard, empty and error states, and a rehearsed demo.

**Stretch (not started)**

LightGBM predictor, cascade routing, semantic cache, a Rust port of the embedding and k-NN, per-key budgets, online learning from playground feedback. See [PLAN.md](PLAN.md).

## Troubleshooting

**`/health` on the router returns `"status":"error"`.**
Check the console for `CRITICAL ERROR during Bifrost ML Service startup`. The usual cause is a missing index. Run `training/train.py` first.

**Router says `No module named app` or cannot find models.**
Run uvicorn from `router-ml/`, not from the repo root.

**Chat returns `502` with "OPENROUTER_API_KEY is not set".**
Set the key in the root `.env` and restart the gateway. Keys containing `xxxxxxxx` are treated as unset.

**Gateway ignores my `.env` when started from the repo root.**
The gateway loads `../.env`, so run `cargo run` from `gateway/`. Environment variables set in the shell always take precedence.

**Playground shows `[mock ...]` replies.**
`BIFROST_MOCK` is `1` in `web/.env.local`. Set it to `0` and restart `npm run dev`.

**Dashboard is empty or shows errors.**
Check `DATABASE_URL` in `web/.env.local` and that `docker compose ps` shows Postgres as healthy. Set `NEXT_PUBLIC_BIFROST_DEMO=1` to see sample data while you debug.

**`docker compose up` fails with port 5432 in use.**
Another Postgres is running. Stop it, or change the host port mapping in `docker-compose.yml` and `DATABASE_URL` to match.

**Index build is slow.**
Embedding runs on CPU. Lower `MAX_CORPUS_SIZE` for a quick run. The checkpoint means you lose at most one batch if you stop it.

**Evaluation numbers don't match the table.**
Check whether `prepare_data.py` used the real RouterBench download or the synthetic fallback.
